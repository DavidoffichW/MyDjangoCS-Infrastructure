# Conformance vectors and independent reproduction

Conformance answers a narrower question than the test suite: can another implementation
produce the same contract values without calling the code under test to generate its
expectations?

The checked-in vectors live in
[`workflows/tests/golden/conformance_vectors.json`](../workflows/tests/golden/conformance_vectors.json).
They contain only small fictional values and are suitable for independent implementations.
The project tests consume these fixed expectations; they do not rewrite them during a run.

## Canonical JSON vector

Input:

```json
{
  "schema_version": "mydjangocs.golden/1",
  "label": "alpha",
  "values": ["1", "0", "-2.5"]
}
```

Expected canonical UTF-8 text:

```json
{"label":"alpha","schema_version":"mydjangocs.golden/1","values":["1","0","-2.5"]}
```

Expected framed identity:

```text
golden:sha256:17eaa71dfe284d45bfa13bffd977fa6f19daf4b576cada3cea026b5e66ea4083
```

An independent checker should:

1. order the object keys by UTF-16 code units;
2. emit compact UTF-8 JSON with the array order unchanged;
3. prefix the bytes with `mydjangocs\0golden\0mydjangocs.golden/1\0`;
4. calculate SHA-256 over the complete framed byte sequence; and
5. prepend the visible `golden:sha256:` domain.

`test_independent_golden_canonical_vector_and_identity` checks both the expected bytes and
identity. The digest was also recomputed with the Windows .NET cryptography implementation,
which does not import the project's identity function. Comparing a function to a value
generated by that same function would only establish self-consistency; the fixed vector and
external digest calculation provide the independent expectation.

## Numerical vectors

| Computation | Inputs used by the reference calculation | Expected value |
| --- | --- | ---: |
| Sensor Alpha time-window mean | `10`, `11`, `12`, `13` | `11.5` |
| Sensor Bravo mean, explicit missing excluded | `20`, `21`, missing, `23` | `21.333333` |
| Sensor Alpha one-hop weighted mean | declared neighbor observations and edge weights | `20.511628` |

The time-window expectations can be reproduced with ordinary exact decimal arithmetic:

```text
alpha = (10 + 11 + 12 + 13) / 4 = 11.5
bravo = (20 + 21 + 23) / 3 = 21.333333 after six-place quantization
```

`test_time_window_means_match_independent_decimal_calculation` calculates the expectations
with a separate Decimal expression rather than calling the method implementation.
`test_reference_decimal_calculation_uses_declared_rounding` independently applies precision
28 and `ROUND_HALF_EVEN`. This matters because an equal digest over an incorrectly calculated
result would still be incorrectly calculated.

The reference semantic and result identities are:

```text
semantic-state:sha256:6edea8182bab6fe1d6b9b46fbeab87332e60b6a21596ffb0a5093b71ac188a83
result:sha256:7d32c02fdb42164d1d1f681906afbe27c380240ec61dc57ba62923ced7adf291
```

The state identity covers the reconstructed state. The result identity covers the accepted
admission, computation, output schema, result values, and state identity. Job UUIDs and
elapsed time are intentionally absent.

## Binary vector properties

An independent binary reader needs no Python object layout. It reads:

- a 52-byte little-endian header with layout `<8sHHII32s`;
- magic `MDSOBS\0\0`, version 1, and flags 0;
- record count and payload length;
- SHA-256 of the complete record payload; and
- fixed 40-byte records with layout `<16sqqBB6x`.

Sensor IDs are ASCII and NUL padded. Timestamps are signed UTC epoch milliseconds. Values
are signed fixed-point integers at scale 1,000,000. Missing values use the declared int64
sentinel and must also set the missing flag. Reserved bytes are zero.

The tests check exact sizes and field interpretation, then deliberately change one bit,
truncate a message, introduce unsupported flags, conflict the missing sentinel and flag, and
provide a sub-millisecond timestamp. Each must be rejected. A decoder that merely reaches
the expected record count is not conforming.

## Run the focused conformance suite

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe manage.py test `
  workflows.tests.test_foundation_contracts `
  workflows.tests.test_memory_binary_store `
  workflows.tests.test_architecture_boundaries -v 2
```

Linux:

```bash
./.venv/bin/python manage.py test \
  workflows.tests.test_foundation_contracts \
  workflows.tests.test_memory_binary_store \
  workflows.tests.test_architecture_boundaries -v 2
```

These checks cover canonicalization, fixed scientific vectors, provenance/state separation,
binary layout and corruption, memory lifecycle, and static dependency boundaries.

## Reproduce the persisted reference experiment

Use a fresh database and artifact directory when comparing repeated executions. The
application accepts both paths through environment variables.

Windows PowerShell:

```powershell
$env:DJANGO_DB_PATH = "$PWD\runtime\conformance.sqlite3"
$env:LAB_ARTIFACT_STORE = "$PWD\runtime\conformance-artifacts"
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py run_reference_experiment
.\.venv\Scripts\python.exe manage.py reconcile_artifacts
```

Linux:

```bash
export DJANGO_DB_PATH="$PWD/runtime/conformance.sqlite3"
export LAB_ARTIFACT_STORE="$PWD/runtime/conformance-artifacts"
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py run_reference_experiment
./.venv/bin/python manage.py reconcile_artifacts
```

Expected properties are:

- two independent jobs succeed;
- the jobs have distinct operational UUIDs and idempotency keys;
- both report the exact result identity above;
- the state identity matches the fixed state vector;
- all registered evidence, manifest, state, and result artifacts verify; and
- reconciliation reports no missing, corrupt, or orphaned blocks.

Re-running the command against the same store should reuse content-addressed bytes and keep
the scientific identities stable. Database primary keys, correlation IDs, durations, file
timestamps, and benchmark measurements are not conformance values.

## Limits of conformance

These vectors cover the named schema versions and their bounded fixture. They are not a
general JSON Canonicalization Scheme certification, a native ABI compatibility guarantee,
a platform performance target, or scientific validation of a physical process. Any future
schema or numerical-policy version requires new explicit vectors rather than silently
inheriting the v1 expectations.
